PROJECT PHOTO TIMELINE OVERHAUL
-------------------------------
- The landing page now shows project folders only.
- Existing projects automatically become folders; no photo re-upload or data
  conversion is required.
- Folder cards display the real project name, address, status, photo count,
  latest update, Before/During/After progress and an authorised private cover.
- Opening a folder displays that project's photos grouped by photo date, with
  the newest date first.
- Gallery and Timeline layouts both keep the date grouping.
- Owners and Admins can upload, edit, select and delete one or many photos.
- A full-screen photo preview provides safe Edit and Delete actions.
- Marketing Booklet, saved reports, Before/After pairs and Company Profile
  remain connected to the selected project.


DELETE FIX
----------
The old deletion function tried to remove a private Storage object directly
from SQL. V48 replaces that unreliable flow:

- the database deletion and cleanup job are recorded in one transaction;
- the authenticated private Storage API removes the real object and thumbnail;
- successful cleanup is marked complete;
- interrupted or failed cleanup stays queued and retries automatically for an
  authorised Owner/Admin on a future Photo Timeline load;
- Before/After pairs linked to a deleted photo are removed by the existing
  database cascade;
- deleting multiple selected photos reports partial failures clearly.


ROLE ACCESS
-----------
- Owner: all authorised projects; upload, edit, single delete, bulk delete,
  marketing approval, booklet and Company Profile controls.
- Admin: all authorised projects; upload, edit, single delete, bulk delete,
  marketing approval and booklet controls.
- Manager: view-only Photo Timeline access.
- Estimator: view-only access; Internal Only photos remain hidden.
- Site Supervisor: view-only access to assigned projects only.
- Worker: no Project Photo Timeline menu or data access.

These boundaries are enforced in both the interface and Supabase functions /
Storage policies.
